# Architecture

## Overview

The app follows **MVVM** with the Observation framework (`@Observable`), Swift Concurrency, and a strict separation of content, presentation state and views:

```
YTA/
├── App/                YTAApp (entry point + background task), RootView (splash, tabs, deep links)
├── Theme/              YTATheme — brand colors, typography, metrics, card & reveal styles
├── Models/             Program, BoardMember, GalleryPhoto, ImpactStat, NewsArticle,
│                       InstagramPost, ContactInfo, CommunityAlert, Poll — value types, Sendable
├── Services/           ContentStore (website content), CommunityAPI (networking),
│                       CommunityStore (alerts/polls state + cache), VideoLibrary, ExternalLinks
├── ViewModels/         One @MainActor @Observable view model per screen
│                       (Home, Gallery, Media, Press, Connect, Community)
├── Views/
│   ├── Splash/         SplashView + AnimatedMeshBackground (iOS 18 MeshGradient)
│   ├── Home/           HomeView — full-screen vertical pager (hero / mission / impact / board
│   │                   pages with snap paging + tappable page indicator, alerts bell)
│   ├── Gallery/        GalleryView + PhotoLightbox
│   ├── Community/      CommunityView — AlertCard + PollCard (animated results)
│   ├── Media/          MediaHubView (channel switcher), MediaView, PressView (in Press/)
│   ├── Press/          PressView + NewsArticleCard
│   ├── Connect/        ConnectView + ContactChip
│   └── Components/     SectionHeader, button styles, CountUpText, TickerView, ConfettiBurst,
│                       LoopingVideoView, VideoPlayerSheet, SafariView
├── Managers/           HapticsManager, NotificationManager, CommunityBackgroundRefresh
├── Extensions/         Color+Hex (incl. dynamic light/dark colors)
├── Resources/          Videos (5 × MP4), Fonts (Outfit ×4, Fraunces ×4),
│                       Seed JSON (sample alerts/polls), Localizable.xcstrings
└── Assets.xcassets     26 imagesets (website images + NGO logo), AppIcon, AccentColor
```

Alongside the app: `Server/` contains the ready-to-upload feed files
(`alerts.json`, `polls.json`, `polls.php`, `vote.php`) and `ADMIN-GUIDE.md`.

The Xcode project is **generated by XcodeGen** from `project.yml` (the `.xcodeproj` is gitignored): everything inside `YTA/` is included in the target automatically — `.swift` files compile, everything else ships as a bundle resource. `Config/Info.plist` supplies the keys that can't be generated (custom fonts, URL scheme, background-task identifiers) and is merged with Xcode's generated Info.plist at build time.

## Data flow

`ContentStore` is created once in `YTAApp` and injected via `.environment(...)`. It holds every piece of website content (hero copy, programs, KPIs, board, gallery, Instagram stats, press articles, contact details) transcribed 1:1 from `index.html` and `assets/js/yta-instagram-feed.js`.

View models own only **presentation state** (selected photo, active video, armed counters, focused carousel card) and side-effect actions (haptics, building Apple Maps URLs). Views bind to both.

## Networking: the community feed

Website content is static and bundled (see below), but the **Community tab is live**. `CommunityAPI` is a `URLSession`/`Codable`/async-await client for a deliberately simple feed the association can host on its existing web space:

```
GET  https://ytalebanon.org/app/alerts.json   → [CommunityAlert]
GET  https://ytalebanon.org/app/polls.php     → [Poll] with live tallies
                                                (falls back to polls.json)
POST https://ytalebanon.org/app/vote.php      → records a vote, returns updated Poll
```

`CommunityStore` (@MainActor @Observable) owns the state with a three-level fallback: remote → last-good disk cache (Application Support) → bundled seed JSON. Votes are optimistic (counted locally, persisted per device, then submitted). Unread tracking lives in UserDefaults and drives the tab badge and the Home bell.

**Background alerts:** `CommunityBackgroundRefresh` runs under `.backgroundTask(.appRefresh(...))`, diffing the feed against known alert ids and delivering quiet local notifications (provisional authorization — no permission prompt). Instant lock-screen push would require APNs; the integration point is documented in `Server/ADMIN-GUIDE.md`.

The ready-to-upload server files (`alerts.json`, `polls.json`, `polls.php`, `vote.php`) and the admin guide live in `Server/`.

## Why website content has no networking

The website itself is fully static — no API calls anywhere in its source (the "Instagram feed" is a hardcoded post list rendering `instagram.com/<id>/embed` iframes; news and programs are inline JS arrays). So the app bundles that content 1:1 and documents the future integration points instead of shipping dead code.

### Integration point 1 — content API
If YTA publishes a content API, convert `ContentStore`'s stored properties to `private(set) var`, add an `async func refresh()` that decodes into the existing models (they are already `Sendable` value types shaped for `Codable` conformance), and call it from `.task` in `RootView`. All screens update automatically through Observation.

### Integration point 2 — Instagram Graph API
`InstagramPost` carries the shortcode, kind and engagement stats the website hardcodes. To show real thumbnails and live counts, exchange a long-lived Instagram Graph API token server-side and replace the static array in `ContentStore.instagramPosts`. `MediaView` renders whatever the store provides; card artwork is the only view code that would change (swap the branded gradient for `AsyncImage`).

## Design-fidelity decisions

- **Colors** are the site's exact CSS custom properties, made dynamic: dark mode moves surfaces onto the navy family the site already uses for its dark sections.
- **Typography**: Fraunces light-italic for display (the site's hero/serif style), Outfit for UI — the same Google font families the site loads, bundled as static TTFs and registered via `UIAppFonts`. All text uses `Font.custom(_:size:relativeTo:)`, so Dynamic Type works everywhere.
- **Animations**: scroll reveals use `scrollTransition` (native equivalent of the site's IntersectionObserver reveals); the KPI count-up matches `data-yta-count`; the marquee matches `yta-ticker`; the gold pulse matches the `flash` keyframes; the lightbox uses `matchedGeometryEffect`. Every continuous animation honors **Reduce Motion**.
- **Instagram embeds** are web-only technology; the native carousel keeps the coverflow presentation, stats and links (opening the Instagram app when installed) rather than embedding web content, per the no-WebView requirement.
- **Map**: the site embeds Google Maps in satellite mode; the app uses MapKit's hybrid style and hands off to Apple Maps for directions — the native-platform equivalent.

## Performance

- All grids/rails are lazy (`LazyVGrid`, `LazyHStack`).
- The hero loop uses `AVPlayerLooper` with a muted ambient audio session (doesn't stop the user's music) and releases the player when the view is discarded.
- The count-up runs a bounded task (45 steps) — nothing animates after it finishes.
- Images ship at the website's own optimized sizes; videos total ≈13 MB.

## Testing notes

The project was authored on Windows, so it has not been compiled here; it targets stable, documented APIs (iOS 17/18 SwiftUI, Observation, MapKit, AVKit). If a build issue appears on first open, it will most likely be signing (select a team) rather than source.
